## 0. 总览

### 0.1 结论

1. **v4（10-31）：**我方 bench 上大幅领先。IF-Bench 全量十种平均 UP 81.1% / JP 50.3%，最强基线 Qwen-Image-2.1 为 64.0% / 29.4%。但外部画质明显差：MIRA 全量 PQ 6.26，原版 7.28。
2. **画质为什么下降（11-04 至 11-06 的诊断）：**有两个独立来源。
   - **高亮（读 token）行上的区域项和干扰物项。**同样的高亮行，在路由之外加上这两项，PQ 降 1.23 [−1.87, −0.65]。
   - **贴回（paste-back）目标。**只用整图损失也伤画质：PQ −0.68，一致性也降。
   - 训练流程本身无害，自检通过。推理时降 LoRA 强度到 0.75 能缓解一点（PQ +0.45 左右），但修不了平涂改色。从 v4 续训少量数据（A/B/C 组、R1）都无效。
3. **新配方（11-06 至 11-09）：**
   - 区域项只加在编辑行上（高亮行为 0），编辑行改用整图生成后还原区域外的高质量合成目标。这样能在同规模下把 PQ 拉到原版水平。
   - 但**从零按新配方训练，bench 有 0.72–0.77 的上限**（IF-Bench 40 例子集 UP，v4 为 0.835），加大规模也没用。
4. **定稿 R2（11-10）：**从 v4 出发，低学习率（8e-6）在高合成目标的行上续训。3.2 万行时两个指标同时最好：IF-Bench 子集 UP 0.835 / JP 0.556，与 v4 持平；MIRA 子集 PQ 对原版 −0.07。再往后训，bench 下降、画质也缓慢变差。
5. **全量验证（11-10 至 11-11）：**
   - IF-Bench 全量 UP 80.3% / JP 49.9%，与 v4 打平，仍远超所有基线。
   - MIRA 全量 PF 7.88、Cons 7.83（都高于原版）。PQ 同时段重判 7.19，原版 7.21。
   - MagicBrush 五项都显著好于 v4。
   - CompBench 与 v4 互有高低。

## 1. 评测口径与判分噪声

后面所有判定都依赖这几套口径，先说明。

### 1.1 IF-Bench

- **全量**（论文主表）：
  - 数据：release 2.6.0，1,084 张图，3,872 个单元，10 种 setting，共 10,840 个请求。
  - 判分：canonical Judge Qwen3.8-Flash-Next-FP8（temperature 0），每个 case 一次联合判全部单元。
  - 指标：单元 E=4 且 P≥3、Q≥3 计为通过（UP）；同图全部单元通过且整图 P、Q ≥ 3 计为整图通过（JP）。
  - 区间：以源图为单位的配对 bootstrap，10,000 次，seed 20261027。
  - 七个基线的全量结果见 `SE/ifbench_merged_final_20261104/MERGED_REPORT.json`；benchmark 文档见 benchmark 仓库 `v2branch:docs/PAPER_RESULTS.md`。
- **40 例快速子集**（开发用）：
  - `QA/ifbench_cases80.txt` 排序后前 40 个 case × S1、S3-mask、S4-noref、S5，共 160 个请求、141 个单元，用同一个本地 Judge。
  - 外部基线的同口径成绩由正式全量 `REPORT.json` 的 per_case 重算（`QA/scripts/ifb_table.py --external qwen21`）。原版 Qwen-Image-2.1 为 0.647 / 0.256。
  - **注意：**表里的 v4 是 LoRA 强度 0.75 时的同窗口重判（0.835 / 0.569，标签 `aa40_s1a_6000`），不是强度 1.0。v4@1.0 在同一子集上是 0.812 / 0.512。
- **本地 Judge 的 A/A 漂移**（`QA/ifbench/aa_rejudge_partial.json`）：同一批输出隔开重判，197 个请求中 UP −0.7 pt、JP +1.5 pt；7.4% 的单元翻转，11.7% 的请求翻转。所以跨会话只比总体，逐例比较必须放在同一次判分会话里。

### 1.2 MIRA

- **30 张子集**（开发用，`QA/mira_eval/sub30/SUBSET30.json`）：
  - 正式 token 设置：Pass1 区域码复用正式 run_001，S2 带 γ=2；GPT-5.4 判分。
  - 每个比较都把原版 Qwen-Image-2.1 和 v4 放在同一批里重评。
  - 对比文件为 `QA/mira_eval/compare_<批次>.txt`，评分目录为 `QA/mira_eval/scores_<变体>_<批次>/`。
- **200 张全量**（`SE/external_mira/`）：v4 与基线判于 11-03；R2 判于 11-11（`SE/external_mira/r2_20261110/`）。
- **GPT-5.4 重判的稳定性**（`QA/ANALYSIS_judge_comparison_20261106.md`）：同一批输出在 6 个批次里重评：

  | | 批次均值范围 | 单张图重评标准差 |
  |---|---|---:|
  | 原版 PQ | 7.09–7.35 | 0.49 |
  | v4 PQ | 6.04–6.29 | 0.72 |

- **两套 Judge 看的东西不同：**MIRA 的 PQ 不看指令，Cons 只看 mask 内；IF-Bench 的 Q 门槛宽，对平涂几乎没有区分力。所以 MIRA 的 PQ 要和 PF 一起看。

### 1.3 开发集 token 探针

- 数据：`V3/data/round2_20261016/eval_c1.json`，1,320 项，常用 `--limit 120`（560 项）或 `--limit 60`（300 项）。

## 4. v5（11-05 至 11-06）：着色高亮 + 高质量数据重训，以及原因诊断

设计在 `QA/PLAN_V5.md` §1–§9，结果在 `QA/RESULTS_V5.md` §1–§12。

### 4.1 高质量数据

- 自蒸馏 v2 批次：原版整图生成 96,050 条 → 通过门限 30,412 条（31.7%）→ 通过语义审核 26,643 条（87.6%）。
- 详见 DATA.md §4.1。

### 4.2 高亮试点（tint，`runs_v5/v5_pilot_tint/`）

- 设置：原 S1 的行，只把高亮换成保纹理着色；`--updates 6000 --stop-after 2000`。
- 开发集全量 1,320 项：盲指代（与风格无关）−0.001 [−0.007, +0.005]，读取不变慢；带名 +0.035。
- MIRA：PQ −0.03 [−0.40, +0.37]，细节比没有提高。
- **结论：**高亮的视觉形式与画质无关。

### 4.3 S1'（`runs_v5/v5_full/s1/`，行 `QA/data_round2_v5/rows_v5_s1.jsonl`）

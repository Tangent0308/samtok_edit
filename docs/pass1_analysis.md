# Pass1 根因分析与下一轮建议

**Pass1 失败分析与下一轮训练建议 — 2026-10-31**

本次重新分析冻结的 IF-Bench 2.6.0 / fairness v2.1 dev20 结果，并核对实际训练代码、选择清单和 step 2000 已消费的 batch。结论是：当前协议、给定 mask 的复制和多种输入的联合输出已经基本学会；更值得投入的是源图目标的语义与范围监督、训练目标与几何质量的对齐，以及 codec 的细粒度重建问题。没有启动新的模型推理、数据生成或训练。

这是 20 张图、72 个独立目标的小规模诊断。509 个未知目标输出是在不同 setting 下重复评测这些目标，不能当作 509 个独立样本；下文的比例和机制解释不等于完整 benchmark 上的因果结论。

**先排除当前证据不支持的主要原因。**

- step 2000 的严格协议通过率为 200/200，给定 mask 的 token 原样复制为 211/211；没有输出截断。当前低 IoU 主要不是 JSON、目标 ID 数量或复制格式的问题。
- 未知目标的 mIoU 为 70.60%；基座按兼容格式计分为 52.22%。因此适配有效，但剩余定位误差依然影响完整请求的成功率。
- 对每个混合 setting 中的未知目标，找到同图、同 U 标签、**自身公开输入字典完全一致**的 S1 / S2 / S3 请求进行配对。双方都是多目标联合推理，差异在其他目标使用的输入形式；这不是单目标与多目标的对照。

| 训练后 setting | 配对目标输出数 | 混合输入 mIoU | 对应同类输入 setting mIoU | 差值，百分点 | 按源图 bootstrap 95% 区间 |
|---|---:|---:|---:|---:|---:|
| S4-ref | 49 | 72.26% | 72.57% | −0.32 | [−0.86, +0.01] |
| S4-noref | 49 | 73.09% | 72.81% | +0.27 | [−0.10, +0.95] |
| S5 | 51 | 68.90% | 68.68% | +0.22 | [−3.18, +4.04] |

这批样本没有显示明显的混合输入损失，不支持将下一轮的重点继续放在“增加普通混合请求”上。样本量有限，也没有进行逐目标独立推理对照，不能据此宣称所有联合推理干扰都已消失。

**1. 能找到相关物体，但对“目标到底是哪一部分”仍不稳定。**

以下是已经核对可视化和原始公开指令的例子。codec 参考指原始 GT mask 经冻结 codec 编码再解码所得的 IoU。

| 案例 | 公开要求与实际错误 | 训练后 IoU | codec 参考 IoU | 判断 |
|---|---|---:|---:|---|
| `sa_455310 / S1 / U2` | 顶层左侧阳台栏杆；预测落到较低楼层的栏杆 | 0.0% | 73.6% | 空间关系和同类实例消歧失败 |
| `sa_8415518 / S1 / U4` | 中间戴头巾者的制服上衣；预测选到了头巾区域 | 0.6% | 80.0% | 用来描述人物的属性与真正被编辑的部件混淆 |
| `sa_5447626 / S2-point / U4` | 在装白花的编织袋上添加价签，应定位袋子；只选到袋子的一部分 | 21.7% | 95.8% | 范围不足，且相对基座 95.8% 出现退化 |
| `sa_5447626 / S3-point / U4` | 同一袋子、同一点，移除文字指代；仍只选到一部分 | 28.6% | 95.8% | 点击在预测内，但 recall 只有 28.7% |
| `sa_10831959 / S1 / U5` | 右侧多色伞的可见伞面；只覆盖部分伞面 | 40.4% | 88.2% | 范围/组件完整性不足 |

袋子面积占图像 8.74%，不能把此例归因于小目标看不清。总体 point 覆盖率已经达到 204/208=98.1%，但 point 的平均 IoU 只有 69.7%，说明“预测包含点击”远远不足以保证目标范围正确。

现有无 ref 单点还存在客观的粒度歧义：一个点可以同时属于物体、部件和局部表面。训练可以改善默认选择，但如果公开信息无法区分两个合理的 GT 粒度，单个确定答案无法保证总能还原标注者意图。应审计这种歧义，而不是给模型加入 benchmark 没提供的私有 scope 字段。

**2. 训练已有混合和反事实数据，但有明确的语义覆盖缺口。**

完整训练集是 159,861 条请求。当前评测使用 step 2000，它实际见到 127,829 条请求，其中主训练 95,856 条；以下区分“完整主集”和“该 checkpoint 实际已见”。

| 指标 | step 2000 已见主训练 | 完整主训练 | 本次 benchmark |
|---|---:|---:|---:|
| 未知目标中的 add | 11,102 / 245,017 = 4.53% | 14,729 / 327,078 = 4.50% | 143 / 509 = 28.09% |
| 带 site、回退到 host 的 add 子集 | 25,969 个目标 | 34,581 个目标 | 不做未经核实的一一类别映射 |
| 上述子集以 mask-copy 监督的比例 | 98.57% | 98.58% | — |
| 上述子集的 text / point 监督 | 0 / 0 | 0 / 0 | 存在添加位置/宿主的 text、point 请求 |
| dense 中性分割目标占全部目标 | 36.33% | 36.41% | 任务为编辑目标定位 |
| 面积 <0.05% 的目标占比 | 0.453% | 0.458% | 2 / 72 = 2.78%，仅两个目标 |

这里的 add 不平衡不是“所有 add 都只做复制”。其他 add 样本确实包含 text/point/box；问题是这一重要宿主子集受模式限制，以及整体未知目标中 add 的权重很低。`has_site` 来自原始 `selection.site`，选数器为了避免将含糊的局部描述硬监督成 host，主动只允许 `noref_box/ref_mask/noref_mask`；后续模式配额使绝大多数落到了 ref_mask。这个保守决定减少了已知标注冲突，也留下了定位训练空白。

这批 benchmark 的 add mIoU 为 61.6%，replace 为 78.6%；两组的 codec 参考和面积组成也不同，因此不能将差值全部归因于数据比例。但是代码中的模式限制和实际曝光比例是已确认的事实，值得优先消融。

完整数据有 12,212 对反事实，step 2000 已见 9,161 对。它们主要保持同图、其他目标、盲指令不变，只在同类 dense 区域间切换一个 no-ref point/box。它们有效训练了坐标依赖，但没有专门构造“顶层/下一层”“戴头巾的人/该人的上衣”“宿主整体/局部部件”这样的文字与粒度反事实。dense 输入统一使用 `Return the segmentation of the selected region.`，不能替代复杂编辑语义监督。

**3. 当前 loss 优化的是唯一 token 标签，不直接优化分割质量。**

实际训练使用 assistant 侧 token 交叉熵，未知 mask code / 已知 mask-copy code / 格式三组权重为 1 / 0.25 / 0.25。反事实配对放在同一个 optimizer update 内，但没有额外的配对排序或对比损失。没有 pixel IoU、边界完整性或 point 覆盖的直接监督。

这个目标已经能学习有效定位，不能说 CE 本身无效。但对剩余错误，单一教师 token 的监督无法表达“几何上几乎等价的另一个代码”与“选择错误楼层的代码”的质量差别。509 个未知输出中仅 141 个与 canonical 两词完全相同，另有 17 个输出的 IoU 比该 canonical 重建高超过 5 个百分点；所以不能仅靠字符串是否等于缓存答案来评估几何准确度。

**4. 一部分可视化差，是给定 mask 本身经过 codec 就重建不好。**

72 个独立 GT 区域的编码→解码平均 IoU 为 74.44%，8 个低于 0.5，20 个低于 0.7。例子包括四块窗玻璃只还原一部分、细小车辆或被遮挡的衣服范围改变。这解释了为何给定 mask token 复制 100% 正确，最终像素 IoU 仍可能很低。

509 个未知输出中有 86 个 IoU<0.5，涉及 19 个独立目标；其中 52 个输出来自 canonical 重建本就低于 0.5 的 8 个目标。同时，仍有 18 个低 IoU 输出对应 canonical≥0.7 的 6 个目标，确实存在 MLLM 定位失败。

这些是共现分层，不是“60.5% 的错误已被证明由 codec 导致”的因果分解。canonical 重建也不是性能上限：其他两词组合有可能更好，前述 17 个输出就是反例。应称其为当前教师/重建参考。增加 TE 的复制训练不能改变完全相同 token 对应的解码 mask。

主训练所有区域的 codec RT≥0.7，本次 benchmark 却有 20/72<0.7，存在表示质量分布差异。85,554 条低质量小区域 reserve 仍未进入训练；直接把它们作为硬 token 教师补入 CE，可能强化错误形状，不能靠降低门槛解决。

**5. 小目标视觉分辨率是待验证的机制，尚未证实是主因。**

当前 processor 上限是 2,097,152 pixels，LoRA 只覆盖语言模型的 attention/MLP，视觉编码器和 merger 冻结。[Qwen3-VL 官方说明](https://github.com/QwenLM/Qwen3-VL)的空间压缩因子为 32；按面积粗算，在约 2M pixels 下，0.05% 区域只相当于约一个最终视觉 token 的面积。这只表示感知压力，不能理解成硬分辨率下限：视觉特征有上下文，细长形状也可能跨多个 token。

本次 <0.05% 只有两个独立目标，mIoU 9.3%，codec 参考也只有 17.3%。因此提高 TE 分辨率能否帮助，必须与 codec 的误差分开检验，不能预先承诺改善。

**建议下一轮按下面顺序推进。以下是待实施方案，不是已取得的结果。**

1. **先补语义与范围监督，保持现有协议、词表和冻结 codec。** 从已隔离的训练源图、真实 D12/D15/D13 编辑单元及现有区域池补 hard cases：add 的源图 anchor、物体与部件、多个相似实例的空间/序数关系、遮挡与不连通组件。先审计 `selection/source_role/scope/target_part` 与公开指令是否对应；不能简单解除所有 `has_site` 限制，把本来含糊的局部描述监督成整个 host。对可明确表达的子集恢复 ref-only/ref-point/ref-box；无 ref point 仅保留公开信息和一致标注政策足够确定的粒度。新增物体轮廓不是源图 Pass1 标签。

   建议第一轮续训起点为 60% 原分布回放 + 40% 经审计的难例请求；让未知目标中的 add 达到约 20–25% 作为初始消融配额，同时检查实际物化结果。配额是方案，不是从这 20 张图拟合出的最优值。保留混合 K=2–5、给定 mask-copy 与各模式的覆盖，不为配额重复少量源图。

2. **扩展反事实的内容，不只是数量。** 同图训练楼层/左右/序数、人物属性与被编辑部件、整体与局部之间的明确文字对比；相同目标用多个有效点击位置时监督相同语义范围。正常训练点现有深内点/均匀/近边界策略已存在，不是需要从零添加的功能。现有训练点必须落在 GT 与 canonical 解码的交集；增加点击位置前，先确保教师能覆盖该点，或修复教师/采用多个可接受代码，避免输入要求点击在内而标签 mask 在外的冲突。

3. **在小规模上加入几何质量排序，先于大规模 RL。** 对训练图的模型输出和缓存教师组成候选库，用冻结 codec 解码，按 GT mask IoU 为主、边界和点击覆盖为辅筛出较好/较差的完整两词序列。候选先用 4–8 个小规模试验；几何指标不足的样本不强行制造正例。用好序列 SFT，并叠加较小权重的成对序列排序，或多正例似然训练。两词必须按有效完整序列评分，不能独立拼接不同候选的 token。

   可以让好序列的 mask-code 条件 log-prob 高于坏序列，其他目标输入与输出前缀固定；这应单独实现并消融，不能把现有配对 co-batch 当作已经做了排序。点击覆盖只能作为约束/辅项，单独优化会鼓励很小的点周围区域；box 约束也不能把预测填满框当作正确答案。保留格式/复制 CE 以免已有能力退化。

   以上 GT 排序只用于训练/离线验收。部署仍是一轮生成每个目标的一组 token，不需要候选重排器或 GT oracle。硬 token 的 argmax 和二值 mask 不可直接求导，不能简单在现有 `generate()` 后加 Dice loss 就认为梯度能传回 TE。先做离线质量排序，验证后再考虑 GRPO。

   [SAMTok 原文 §2.3](https://arxiv.org/html/2601.16093v2#S2.SS3)确实使用了文本答案匹配的 GRPO。那是原论文的方案；这里建议额外评估几何质量，是针对当前教师重建误差和编辑粒度要求提出的实验，不能当作已经验证的 SAMTok 配方。

4. **把 codec 难例分成可修复教师和当前不可表达两类。** 在训练侧用原图与原 GT mask、冻结 codec 进行候选代码验收；如果找到更好的同词表代码，可以更新新实验副本中的教师标签并保留原标注与来源。如果候选都不好，单列表示困难集，先不以错误硬标签推动 TE。当前优先保持 codec 与两词定义稳定；直接重训 codec 可能改变 Pass2 已学到的 token 区域含义，应是后续独立兼容性实验。

5. **用受控消融确认分辨率和续训收益。** 先固定模型，在独立 hard dev 比较 2M 与 4M pixel 上限，保持同一原图和全局坐标，codec 输入/解码规则固定。分辨率若有效，再做训练端匹配；不要用 GT 定义 crop 输入模型。当前没有证据需要先增大 LoRA rank、全面解冻 vision 或换 TE。

具体可先做等训练预算的 300–500 update 续训消融：A 为原配方继续训练，B 仅改审计后的难例/覆盖，C 在 B 上增加几何排序；分辨率另做固定权重对照，确认后才加入训练。仍从 step 2000 的 rank-64 LoRA 出发，学习率 5e-6–1e-5 是待验证的起点；不能直接续用快走完的原 scheduler 而不重设。现有 dev 从 step 2000 的 75.95% 到 2502 的 75.90% 已基本持平，未证明过拟合，但没有证据表明仅延长同配方能解决这些结构性缺口。

检查点选择应同时看原 dev 的未知目标 IoU、独立 hard dev 的 add/part/spatial/small 分组、整条请求 all-IoU≥0.5、格式和 mask-copy 保持情况。hard dev 必须按源图隔离；本次 20 张 benchmark 图及其标签不进入训练，正式 benchmark test 不用于调参。对候选教师质量低的集单独报告，避免把 codec 和 TE 的变化混成一个数字。Pass2 继续关闭此 LoRA，复核 adapter-off 与原 TE 一致。

# SAMTokEdit Qwen-Image-2.1 v3：方法

本文说明 v3 的方法：每个部件是什么、为什么加、在哪一步加入、代码在哪里，以及参考了哪些工作。
- 数据见[文档 01](01_SAMTokEdit_Qwen21_v3数据.md)，实验和结果见[文档 03](03_SAMTokEdit_Qwen21_v3实验.md)。
- 代码细节和命令见[文档 04](04_SAMTokEdit_Qwen21_代码实现说明.md)。
- v2 问题的完整证据见[文档 06](06_SAMTokEdit_Qwen21_v2分析.md)。

代码路径相对仓库根目录。截至 2026-10-19，代码分支 `qwen-image-2.1-v3`。

## 0. 一句话方法与验收口径

**方法。**编辑区域由 SAMTok 的 codec 编码成 4 个 token 的 mask 片段 `<|mt_start|><|mt_XXXX|><|mt_YYYY|><|mt_end|>`（下文记作 ⟨M⟩），直接写进编辑指令。
- 冻结的 Qwen3-VL-8B-SAMTok 文本编码器（TE）编码整句。
- 码本注入模块（CodeInjector）在 ⟨M⟩ 的位置补上码本向量。
- Qwen-Image-2.1 DiT（原权重 + LoRA）按这个条件编辑。
- **推理时不解码像素 mask，不加注意力偏置，不做 latent 融合。**mask 只在训练时使用：构造目标图、损失权重和注意力监督标签。

**验收口径（用户 2026-10-18 决定）。**只看带 token 的编辑，必须好于原版：
- 用户给区域，编成 token；
- 或者以后由 TE 从文字指令生成 token（第一遍）。

不带 token 时比原版差可以接受。因此不需要为保住无 token 能力加纯文字数据，benchmark 的纯文字分数也不作验收。

## 1. 出发点：v2 的问题

v1 训练 TE 学定位（第一阶段定位 LoRA）、再训练 DiT（第二阶段）。v2 为了消除 v1 的副作用，改成 DiT 条件用**原始** SAMTok TE（`pass2_te="raw"`），并试了把 codec 解码出的区域作注意力偏置（E5）和不加偏置（B0）两种。

2026-10-11 的复核（文档 06）结论如下。v3 的每个部件都对应其中一条或几条：

| # | v2 的问题 | 证据（摘要） | v3 的对应 |
|---|---|---|---|
| P1 | **DiT 生成时不读 mask token**（核心） | 同图同句只换 token（删除，120 对）：E5 两次都跟对 0.06，B0 0.20；E5 换成 codec 区域偏置后 0.75 | 让 token 成为降低损失的唯一途径：路由损失、指认任务、近邻反例 |
| P2 | mask 当输入是捷径 | 训练时带区域偏置的 E5 比不带的 B0 更不读 token | mask 只作监督，不作学生输入 |
| P3 | 只用编辑对的 FM 损失教不会 token 含义 | FM 误差约 97% 在区域外；有物体名时模型读名词就够（读取 0.27，和 token 相当）；区域边界脏 | 盲指代（no-ref）指令、区域面积归一损失、精确目标 |
| P4 | 换 TE 本身伤 add / remove | 只换 TE 权重，add 框内改动面积 −21% | 计划混合 TE（未实现）；第二轮用原版自己生成的 50k 编辑做自蒸馏 |
| P5 | 学会整图缩放重取景（漂移） | 不融合时 B0 20%、E5 17% 的输出有整图相似变换 | 数据清洗剔除错位对；漂移目标只算局部损失 |
| P6 | 学会"软补丁" | 贴回清洗后编辑区锐度只剩周围的 0.62–0.70 | 目标逐像素精确的数据（指认、50k 精确支撑域） |
| P7 | 小部件太小 | 训练 attribute 面积中位 6.3%，dev 0.49%；1 MP 下 0.3% 的部件只有 2–3 个 latent token | 区域池按面积桶抽样，贴近 benchmark |
| P8 | 数据语义缺陷被模仿 | "删除座椅"实为涂色，material 编辑退化成 replace | 协议 1.0/2.0 重写指令，清洗 |
| P10 | token 读得出身份，读不出范围 | 读出头约 75% 选对实例，但 IoU 最多 0.50；码本向量比 DiT 第 12 层读得更好（+0.15） | 码本注入（CodeInjector） |
| P12 | 原版只缺"删除时填背景"的先验 | 原版 + 区域偏置 attribute 1.00、add 0.82 | 编辑以原版能力为基础，LoRA 只补读 token |
| P13 | v1 的能力走间接通路，代价大 | 位置写进 ⟨M⟩ 之后的模板 token；条件余弦相似度 0.786，严格成功率 0.63→0.27 | 不训练 TE，pass 2 用原始 TE |
| P14 | 架构约束 | 联合序列 [文本前缀 \| 源图 latent \| 指令 \| 目标 latent] 是 block-causal 的，源图 token 看不到 ⟨M⟩ | 读取只能发生在 ⟨M⟩→源图、目标→⟨M⟩/源图，路由损失正好监督这两处 |

## 2. 设计原则

1. **推理形式不变。**用户（或 VLM）给区域 → SAMTok token → 写进指令 → DiT。不解码、不偏置、不融合。这是项目固定的创新点。
2. **mask 只作监督，不作输入。**它用于目标图、损失权重和注意力监督标签。依据 P1、P2。
3. **让 token 成为降低损失的唯一途径。**做法：
   - 用盲指代指令（协议 2.0：no-ref 一律写 "the selected region"）；
   - 加同类或近邻干扰；
   - 损失按区域面积归一；
   - 目标逐像素精确。

   依据 P3。
4. **保住原版能力。**
   - 编辑数据用原版自己生成的结果（50k 自蒸馏）；
   - LoRA 小（rank 32）。
   - 混合 TE 计划过，至今未实现。
5. **token 只需给无歧义的身份，不必给像素级边界。**精确边界交给生成器先验（文档 06 §5.5）。

## 3. 整体结构

```
训练与推理共用的条件路径
  指令文字（含 ⟨M⟩） ─► Qwen3-VL-8B-SAMTok TE（冻结，取最终 RMSNorm 之前的隐状态）
                         │
                         └─► + CodeInjector：⟨M⟩ 的码位置加码本向量的线性投影
                                   │
  源图 ─► VAE ─► 源图 latent ─┐     ▼
                              Qwen-Image-2.1 DiT（冻结 + LoRA r32）─► 目标 latent ─► VAE ─► 输出
只在训练时用的监督（不进入推理）
  token 的 codec 解码区域 / 实际改动像素 / 邻居与孪生区域
     ├─► 区域面积归一的 FM 项、邻居区域 FM 项
     └─► 注意力路由损失：写（目标 token→⟨M⟩）、读（⟨M⟩→源图 token）
```

推理入口是 `src/samtok_edit21/evaluation/grounding.py::generate`，它调用：

```
edit(pipe, prompt, [src], mode="inline", pass2_te="raw", binding=BindingConfig("none"), blend_region=None, cfg_scale=1.0, use_kv_cache=True)
```

推理设置：
- 画布约 1 MP，保持宽高比，边长取 32 的倍数（`canvas`，`CANVAS_AREA = 1024*1024`）。
- 输出合成到白底后缩放回原图尺寸，和 benchmark 的打分口径一致。
- dev 评测用 20 步，benchmark 拆分 case 和对比页用 40 步（官方默认）。

## 4. 部件

### 4.1 底座 DiT 与 LoRA
- **底座：**Qwen-Image-2.1，单流 MMDiT，32 个 block，宽 4096，32 头，bf16，冻结。一个目标 token 对应 16×16 像素。代码：`src/samtok_edit21/models/pipeline.py::load_pipeline`。
- **LoRA：**PEFT LoRA。
  - rank 32，alpha 32，dropout 0。
  - 目标模块是 DiffSynth 自动检测出的 `to_q`、`to_k`、`to_v`、`to_out.0`、`proj`、`out`、`gate_layer`。
  - 共 83,886,080 个参数，可训练参数转 fp32。
  - 代码：`src/samtok_edit21/training/objectives.py::add_adapter`。
- **为什么：**生成器要学会读 token（P1）。原版缺的只是读 token 和少量先验（P12），小 LoRA 足够，也少伤原版能力。
- **可训练参数合计：**
  - 第一轮（E-A2）87,044,108 = LoRA + 注入 3,158,016 + 写方向仿射 12；
  - 第二轮 87,044,120，再加读方向仿射 12。

### 4.2 文本编码器与两遍设计
- **TE：**Qwen3-VL-8B-SAMTok，冻结。
  - 取最终 RMSNorm **之前**的隐状态（forward pre-hook）。
  - 分词器和对话模板换成 SAMTok 的，确保 514 个 mask 相关 token 各是单个 token。
  - 代码：`src/samtok_edit21/models/pipeline.py::SamtokTextEncoder`。
- **两遍设计**（`edit(..., pass2_te="raw")`）：
  - 第二遍，也就是 DiT 条件，关掉 TE 上的全部 PEFT 层，等于原始 SAMTok TE。
  - 第一遍（`mode="online"`）由 `localize()` 在 TE 适配器打开时生成区域。
- **为什么：**v1 训练 TE 改坏了文本条件（P13）。DiT 的训练和推理都用原始 TE，两边就一致。
- **现状：**v3 的训练和评测只用 `mode="inline"`，token 由用户 mask 编码得到。
  - "用 TE LoRA 从纯文字指令生成目标 token（add 生成锚点）"是用户 2026-10-18 定下的后续方向，还没开始。
  - 代码已经支持 `pass2_te="raw"`、`te_adapters`、`localize`。

### 4.3 SAMTok codec：token 的定义
- **编码方式：**VQ-SAM2，两级残差量化，每级 256 个码。一个 mask 编成 2 个码：第一级写成 `<|mt_0000|>`–`<|mt_0255|>`，第二级加 256，写成 `<|mt_0256|>`–`<|mt_0511|>`。代码：`src/samtok_edit21/models/codec.py::SamtokCodec`。
- **token 的含义以 `decode_strict` 的解码区域为准。**训练目标、路由标签和评测 IoU 都用它；第二轮评测另外报和标注 mask 的 IoU（`iou_gt`）。
- **小区域：**解码精度会下降。
  - benchmark 2.6.0 拆分 case 里，0.08% 的区域往返 IoU 只有 0.37；
  - 第二轮数据把往返 IoU < 0.5 的样本排除在外（文档 01 §4）。

### 4.4 码本注入（CodeInjector，E-A2 加入）
- **注入方式：**
  - ⟨M⟩ 片段的第一级码位置加 `W0·e0 + b0`，第二级码位置加 `W1·e1 + b1`；
  - `<|mt_end|>` 只在紧跟两级码时加 `W2·(e0 + e1) + b2`，即量化后的 mask 表示；
  - `e0`、`e1` 是 codec 的码本向量（256 维）。
- **初始化与参数：**3 个 `Linear(256→4096)` 全零初始化，未训练时和原版逐位一致；共 3,158,016 个参数。
- **梯度与校验：**模块加在 TE 输出上，TE 主干在 `no_grad` 下，梯度只进注入模块。保存时写入码本指纹，不符则拒绝加载。
- **代码：**`src/samtok_edit21/models/code_injector.py::CodeInjector`、`attach_code_injector`。
- **为什么：**v2 的探针显示，码本向量本身比 DiT 第 12 层更能读出区域（no-ref +0.15，P10）。让 DiT 直接拿到码背后的几何，比让它硬记 512 个 id 容易。

### 4.5 注意力路由损失（写方向 E-A2 加入，读方向 C1 加入）
- **监督对象：**block 内真正送进注意力的 query/key 的 pre-softmax 内积。
  - 按 block 的前向重算 norm1 → 时间步调制 → `to_q`/`to_k`（含 LoRA）→ RMS norm → RoPE，再对头和 ⟨M⟩ 的 4 个 token 取平均。
  - 用 forward pre-hook 读取，不改前向。和非重入的梯度检查点配合使用。
  - 代码：`src/samtok_edit21/training/routing.py::span_attention_logits`、`span_read_logits`、`AttentionRouter`。
- **两个方向：**
  - 写：每个目标 token 对 ⟨M⟩ 的平均 logit。正例是区域覆盖率 > 0.5 的目标 token。
  - 读：⟨M⟩ 对每个源图 token 的 logit。正例在源图 latent 网格上。
- **监督层：**`(6, 10, 14, 18, 22, 26)`，共 32 个 block。
- **标定与损失：**
  - `calibrated = scale·(logit − mean)·4 + bias`；每层每个方向一对 (scale, bias)，初值 (1, 0)。
  - 损失是带权二元交叉熵（BCE），写读两个方向形式相同。
  - 正例和反例各占总权重的一半，小区域因此不会被淹没。
  - 落在"重反例"上的反例权重 × `heavy_weight`：E-A2/C1 为 3，C1b/C2 为 8。
  - 第二轮里，如果没有任何 token 覆盖率 > 0.5，就取覆盖率最大的 token 作正例（`round2.py::token_labels`），小于一个 token 的区域也有正例。
- **重反例：**
  - 写方向：邻居/干扰区域（覆盖率 > 0.5），以及同一句里其他 ⟨M⟩ 的区域。
  - 读方向：其他 ⟨M⟩ 的源图区域；C1b 起加上源图网格上的邻居区域。
- **系数：**写 `λ_route = 0.05`，读 `λ_read = 0.05`。路由项不乘时间步权重。
- **为什么：**直接监督"哪些目标 token 应该去看 ⟨M⟩"和"⟨M⟩ 应该去看源图的哪里"。
  - v1 的读取损失曾把读取 IoU 从 0.21 提到 0.49（文档 06 §4.1）。
  - 读方向的好处：⟨M⟩ 对干净源图的注意力在所有去噪步都相同，监督稳定。
- **勘误：**旧文档 08 §5.3 写的读方向"与区域内均匀分布做 KL 散度"没有实现；实际和写方向一样用带权 BCE。

### 4.6 指认任务（E-A1 加入，C1 起改为协议 2.0 写法、加多 token）
- **任务：**让模型在 ⟨M⟩ 指的区域上叠 0.5 透明度的颜色，区域外与源图逐像素相同。输出本身就是区域，损失直接关于 token；同图多实例时，不读 token 就降不下损失。
- **第一轮**（`src/samtok_edit21/data/highlight.py`）：
  - 4 个模板 × 8 种颜色；
  - 指代写法：带物体名时为 `"<phrase> <M>"`，不带时为 `"this region <M>"`；
  - 另有程序化局部编辑（灰度、提亮、压暗、模糊、反色，只作用在区域内），防止 LoRA 只学会上色。第二轮不再使用。
- **第二轮**（`src/samtok_edit21/preparation/round2_data.py`）：
  - 写法改为协议 2.0：no-ref 是 `the selected region <M>`，ref 是 `the <category> <M>`；
  - 多 token 指认一次 2–5 个区域，各用 6 种高区分度颜色中不同的一种；区域互不重叠，排除宿主/部件/重复标注；
  - 区域池按面积桶抽样，< 0.5% 的约占 45%，贴近 benchmark 的区域大小（P7）。
- **读回评测：**把"输出 − 源图"投影到"颜色 − 源图"方向，得到透明度，阈值化成 mask；在完美叠色上读回 IoU 为 0.99。
- **参考：**InstructDiffusion 用同样的形式（源图叠 0.5 透明色块）做指代分割。区别在于：v3 的指代对象是 SAMTok token，mask 只作监督，并用"同句换 token"验证。

### 4.7 反例、反事实成对与近邻硬反例

| 阶段 | 反例从哪来 | 用于 |
|---|---|---|
| E-A2 | 同图其他 token（最多 3 个）的解码区域 | 路由重反例 ×3；邻居 FM 项 |
| C1 | 同类前 3 个 + 第 1 个宿主（部件不作反例） | 同上 |
| C1b | **近邻**：框间距 ≤ 图像对角线 5% 的任意类别标注物体，最近的 ≤ 6 个，再加 ≤ 2 个宿主；用标注 mask | 读写两个方向都作重反例，×8 |
| C2 | 50k 编辑行同 C1b；孪生行再加对方的源 mask | 同上。v1 单条和 D4 行没有邻居反例 |

- **为什么改成近邻：**C1 单 token 失败中 35% 是涂到旁边的相似物，而 C1 训练行里最近的同类只有 52% 被用作反例，异类邻居一个都没有。C1b 因此改成"距离最近的任意物体"。
- **反事实成对（C1b 起）：**单 token 指认行中 30% 成对。
  - 一对的两行同图、同句、同模板、同色，只换 token，各以对方区域为反例；
  - 两行放在同一张卡、同一次更新的相邻两步（`place_in_slots`）。
  - 其中 30% 是部件/宿主对，其余是相邻、面积比 ≤ 4、互不相交的区域。
  - C1b 共 2,112 对，C2 的指认部分有 1,018 对。
- **多 token 相邻组：**40% 的多 token 指认行围绕一对相邻区域构建。

### 4.8 编辑损失（第二轮，C2 定型）

```
loss = w(t)·( FM + λ_region·FM_region + λ_distractor·FM_distractor ) + λ_route·write + λ_read·read
```

- **时间步：**和官方 `FlowMatchSFTLoss` 完全一致。
  - 在 1000 个训练时间步中均匀抽样（Qwen-Image 的 shift 模板）；
  - `x_t = (1−σ)·x0 + σ·ε`，回归目标 `ε − x0`；
  - `w(t)` 是以 t=500 为中心的高斯权重。
- **FM：**逐 token 平方误差的全图平均；样本带 `loss_mask` 时只在 mask 内平均。
- **FM_region：**区域内平方误差，按覆盖率加权并按面积归一。区域外扩 1 个 token 作上下文（3×3 max-pool），多个区域先各自归一再平均。各类样本的区域取法：
  - 指认行：token 的解码区域；
  - C1/C1b 的 50k 编辑行：执行区域（support），不外扩；
  - C2 的 50k 编辑行：实际改动像素（`edited_region`），外扩 1 个 token；
  - C2 的 v1 行：依次取改动像素 → 执行区域 → 选区中第一个非空的；
  - D4 多目标行：每个单元用 `unit_change` 切出自己的改动。整对改动 ∩ 本单元区域外扩 max(4, 1% 对角线) 像素（SciPy EDT 实现，避开集群镜像缺 libxcb 导致的 `cv2` 导入失败）。
- **FM_distractor：**邻居/孪生区域（覆盖率 > 0.25）上的平方误差均值，目标是源图，意思是"别的不许动"。注意它的阈值和路由重反例的 0.5 不同。
- **局部损失（`loss_mask`）：**v1 和 D4 里有些目标图在编辑区外也有改动（区外平均差 > 1.0，或差 > 8 的像素占 2% 以上）。这些行的 FM 只在编辑相关像素外扩 2 个 token 的范围内计算，不让模型学整图漂移（P5）。C2 中 v1 有 9,786 行、D4 有 1,576 行用了局部损失。
- **系数：**`λ_region = 1`，`λ_distractor = 1`，`λ_route = λ_read = 0.05`。
- **代码：**`src/samtok_edit21/training/round2.py::round2_loss`、`region_error`、`unit_change`、`_prepare_edit*`。
- **已知缺陷（2026-10-19 诊断，文档 03 §5.4）：**
  - 50k 编辑区域很小。外扩一圈后，真正改动的像素在 FM_region 里只占：add 7%，remove/attribute 25%，replace 33%（v1 为 64%–71%）。
  - 邻居和孪生的惩罚却始终不打折。
  - 模型拿不准指的是哪个物体时，均方误差下最划算的做法是把改动压小，这是"不执行"的主要来源之一。

### 4.9 多目标提示与拼合（C1 多 token 指认，C2 多目标编辑）
- **多目标编辑写法**和 benchmark v2 的单元编号一致：
  - 第一行 `Execute all numbered instructions and keep everything else unchanged.`；
  - 之后每行一条 `U{k}: <句子>`，每行一个 ⟨M⟩，单元顺序随机打乱（`multi_edit_prompt`）。
- **50k 同图拼合（`edit_multi`）：**
  - 每组 2/3/4 个单元，权重 0.40/0.35/0.25，各单元操作互不相同；
  - 执行区域在 32 像素粗网格上外扩一格后不相交；
  - 50k 的单条目标在执行区外与源图逐像素相同，所以联合目标 = 源图 + Σ（各单条目标 − 源图）。
- **D4（`edit_multi_v1`）：**清洗后的 v1 多目标对，目标是真实的联合编辑结果。
- **监督：**每个 ⟨M⟩ 的路由以其他目标区域为重反例，每个目标区域的误差分别归一后平均。

### 4.10 孪生（C2）
- **定义**（旧文档 06）：同一张源图、同一句 no-ref 指令、两个同类实例各一张目标图，只差 token。这样就去掉了"只看文字就能分清"的退路。
- **C2 实际用的是 50k 里的天然孪生：**
  - 同一源图上 `instruction_noref` 逐字相同的记录，按框间距最近两两配对；
  - 共 6,590 对、13,180 行，强制用 no-ref；
  - 对方的源 mask 作重反例，一对放在同一次更新。
- **副作用：**50k 的 remove 行 92% 是孪生，attribute 28%，add 7%，replace 2%。C1b→C2 退步的正好是孪生多的 remove 和 attribute（文档 03 §5.2、§5.4）。
- **数据侧单独构造的孪生（D6）在 C2 时还没有使用。**

### 4.11 指令写法（协议 2.0）
- **no-ref：**一律写成 `the selected region`；源 mask 是实际被编辑的区域，add 时是附着处。
- **token 的位置：**`instruction_protocol_v2.render(spec, has_ref, selector_token=span)`。
  - no-ref 时 ⟨M⟩ 紧跟在 `the selected region` 后面；
  - ref 时 ⟨M⟩ 接在被指代对象（add 是锚点）后面。
- **编辑行的写法比例：**
  - C1/C1b：盲指代 + token 65%、物体名 + token 20%、只有物体名 15%；
  - C2：盲指代 + token 65%、物体名 + token 35%，没有不带 token 的行；因孪生强制 no-ref，实际比例约 70/30。

### 4.12 其他训练细节
- **画布：**训练画布最大 1 MP，只缩不放，宽高都取 32 的倍数（`data/io.py::dimensions`）。
- **各卡同步初始化：**模型建好后，把 0 号卡的全部可训练参数广播给所有卡；开始时和每次保存时核对校验和（`grounding_engine.py::broadcast_parameters`）。
  - 起因：E-A1/E-A2 的脚本按卡号设种子后才建 LoRA，导致 8 张卡的 LoRA-A 各不相同。
  - 修正后，20 次更新的 mse 从 0.0407 降到 0.0364。
  - E-A1/E-A2 的权重和评测仍然有效，只是训练效率受损。
- **批次顺序：**每次更新的样本只由行号决定：第 `(u·acc + s)·world + r` 行由第 r 卡在第 u 次更新的第 s 步处理。所以 8 卡 × 4 步累积和 32 卡 × 1 步，每次更新的样本完全相同。

## 5. 各阶段的方法演进

| 阶段 | 相对上一阶段改了什么 | 为什么（对应的发现） |
|---|---|---|
| E-A1 | 原版 + 新 LoRA；单 token 指认 + 程序化局部编辑 + 少量真实编辑；区域 FM 项 | 先验证"指认任务能不能让 DiT 读 token"（P1、P3） |
| E-A2 | 加码本注入、写方向路由损失、邻居 FM 项；加 GRES 指认数据 | E-A1 只到实例级部分可用（同句换 token 跟随 0.53），需要更直接的监督（P10） |
| C1 | 改成协议 2.0 写法；加读方向路由；多 token 指认；SA-1B dense mask 区域池按面积桶抽样；从原版重训 | benchmark 区域很小、一图多目标、四种定位方式，E-A2 的 dev 和 benchmark 不一致；用户要求从原版重训 |
| C1b | 近邻硬反例（任意类别，读写都加重，×8）；30% 反事实成对；40% 相邻多 token 组；余弦学习率 | C1 失败中 35% 是近邻，且近邻几乎没被用作反例 |
| C2 | 编辑为主：用上全部可用的 50k / v1 / D4 编辑；区域项改为实际改动像素；漂移目标用局部损失；多目标编辑；50k 天然孪生 | 用户要求编辑能力至少不降、尽量用全数据；C1/C1b 的编辑只占 15% |

## 6. 参考的工作

只列旧文档里实际引用过的工作（旧文档 03 §2，旧文档 08）。当时的说明是"快速检索得到，非完整调研"。

| 工作 | 是什么 | 本方法借鉴了什么 / 区别 |
|---|---|---|
| SAMTok（arXiv 2601.16093） | 把任意 mask 编成 2 个词，用于多模态大模型的理解和分割 | 区域表示和 codec 的来源。它不涉及生成侧怎样使用这些词 |
| InstructDiffusion（arXiv 2309.03895，CVPR 2024） | 把指代分割写成"给物体叠半透明色块"，和编辑联合训练 | **指认任务形式的直接先例。**照搬两条经验：半透明好于不透明，指令写得越详细越好。区别：它用语言指代，目的是分割 |
| Emu Edit（arXiv 2311.10089，CVPR 2024） | 16 种任务联合训练，检测/分割写成生成任务 | "感知任务和编辑混合训练能提升局部编辑"的证据，所以指认和编辑放在同一个 LoRA 里混训 |
| TokenCompose（CVPR 2024） | 用分割 mask 监督文生图模型里名词 token 的交叉注意力 | 注意力路由监督的先例。区别：它针对文字名词，本方法针对离散的区域 token |
| Painter、InstructCV | 把分割等感知任务写成图像生成 | "在输出端解引用"的更早先例 |
| RePlan（arXiv 2512.16864） | VLM 规划器输出区域框，免训练地注入 MMDiT 注意力 | 区域作为**输入**。v2 的"codec 解码 → 注意力偏置"机制和它高度重叠，v3 因此不再这样做 |
| FireEdit（arXiv 2503.19839，CVPR 2025） | 检测器候选框的 ROI 特征作区域 token 放进 VLM 指令 | 连续特征，没有精确指代，也没有"换 token 跟随"的验证 |
| AdaptEdit（arXiv 2604.23763） | 冻结 DiT + 每层适配器、空间门控、编辑区域预测头 | 区域只从文字推断。"区域门控 + 改动像素损失"不能算本方法的创新 |
| Appearance Pointers（arXiv 2607.19344）、FOCUS（arXiv 2506.16806） | mask 经 VAE 编成区域 token，或预测 mask 作空间条件 | mask 作为输入，不是离散语义 token，也没有换 token 验证 |
| InfoNCE 实例对比 | 旧计划 A2：⟨M⟩ 状态和实例区域平均特征做对比学习 | **未单独实现**，作用由路由重反例和邻居 FM 项承担 |

**可以主张的创新点**（旧文档 03 §2）：
1. 区域统一成离散的 SAMTok token，作为指令里的词注入 DiT；
2. mask 只作训练监督，生成器学会在输出端解引用；
3. 可验证的反事实 token 控制：同一句话换一个 token，就换一个被编辑的实例；
4. 两条诊断发现：TE 冻结、只用编辑对训练时，生成器会忽略区域 token；训练 TE 去读位置会改坏文本条件。

## 7. 已知局限和下一步

| 局限 | 现状 | 下一步（未执行，待确认） |
|---|---|---|
| **不执行**（C2 最多的失败） | 开发集 C2 带 token 不执行 50%（C1b 45%，原版 63%）。这是置信度问题，不是能力问题：换 3 个种子，任一执行的有 67%；写明物体名后执行 66%。benchmark 子集 93 个编辑失败里有 38 个没执行，原版、FLUX.3 也一样多 | C3a：区域项只算实际改动的 token，不外扩。推理侧先试 token 引导。C3a 之后仍多，C3b 再把邻居项降到 0.5 |
| **训练目标做了一半** | 50k 的 replace 11.5%、attribute 11.2% 改动不到目标的一半；add 10.2% 改坏了锚点。对应 C2 的叠加、只改一部分、改坏附着物 | C3a 不再使用这些行；C3b 补结构替换和整体改属性的新数据 |

| 近邻失误 | 单 token 指认 C2 命中/旁边/远处 = 59%/31%/10%；同类对的两个 token 98% 码不同，瓶颈在 DiT 区分近邻的精度 | 观察项；benchmark 上改错位置三家相当 |
